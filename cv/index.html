PEGATRON | Senior Software Engineer | 2026 – Present

Context

PEGATRON expanded into server repair operations, requiring a new Order Management module to coordinate the full repair lifecycle across two manufacturing sites. Each repair case is modeled as an order with inbound intake of defective servers and outbound shipment through the existing Pick, Pack, and Ship workflow. The module sits at the integration center — bridging Inventory, carrier services, and repair-line operations — so reliability matters more than throughput at this stage.

Role

Sole backend engineer designing and building the Order Management module from scratch — owning the domain model, lifecycle states, and integration contracts with Inventory and carrier services. Concurrently contributing to the new Vue 3 front-end alongside two other engineers. Backend design has been refined through ~3 months of iterative build-and-validate cycles with PM and operations stakeholders.

Technical Highlights

  • Decoupled inbound and outbound flows into separate orders rather than a single repair lifecycle, since they share no operational coupling in the existing process — keeping aggregates small, simplifying state transitions, and avoiding artificial coordination between flows that operate on different timelines.
  • Designed resilient integration boundaries via a dedicated sync module and anti-corruption layer for the legacy Inventory system, which lacks event-bus support. Failure-prone external calls are isolated in dependent aggregates (e.g., the Pick aggregate) with explicit in-flight states and clean rollback semantics — every cross-module breakpoint is designed to leave the system in a recoverable state.
  • Chose iterative build-and-validate over design-first for a domain no stakeholder fully understood up-front. Each design version is implemented end-to-end and validated against real workflow scenarios, surfacing requirement drift early and building shared understanding across PM, operations, and engineering.

Impact

Module was deliberately scoped around generic inbound/outbound order patterns rather than the specific server repair business — making the design directly reusable for other inbound/outbound workflows across factories, well beyond the original use case. The build-and-validate methodology applied here is gaining visibility within the department, recognized as a productive alternative to design-first delivery — though current adoption remains limited to this project.

Sydney PEGATRON | Senior Software Engineer | Jul – Oct 2025

Context

Sydney is one of PEGATRON's repair factories, handling mobile and computer repair across ~20 production lines and 100+ part types. The HQ Inventory module did not cover line-side stock — the staging area between main inventory and the production line where operators draw parts during repair. This left two operational gaps: defective components returned from the line lost traceability, and operators could pick newly-arrived stock, breaking FIFO requirements for repair operations. Since Sydney couldn't modify HQ services directly, the team built a local satellite service extending the Inventory module to close those gaps.

Role

Sole software engineer, on-site in Sydney for ~3 months, owning the service end-to-end from architecture through deployment. Worked with a PM and a domain expert recently promoted from the production line — pairing technical mentorship for their software ramp-up with their deep operational knowledge to shape design decisions.

Technical Highlights

  • Replaced mouse-driven data entry with a strict scan-sequence flow for the material runner binding returned components to request slips. The original interaction required clicking each field then scanning; the new flow enforces a fixed scan order so each scan auto-populates the corresponding field — trading UI flexibility for speed and reduced input errors during return handling.
  • Closed the chain-of-custody gap between material runner and warehouse by requiring explicit warehouse acknowledgment on return drop-off. The previous workflow had no system-level confirmation when defective parts physically reached the warehouse, leading to recurring lost-control issues. The new feature holds the return open until warehouse staff acknowledge receipt — converting a one-sided handoff into a two-party verifiable event.
  • Adopted constraint-driven UX as operational guardrails — both the scan-sequence flow and the warehouse handoff intentionally remove operator discretion to enforce correct process. In a factory where operators are time-pressured and procedural compliance varies, software-enforced flow proved more reliable than training-enforced flow alone.

Impact

The 3-month engagement delivered the return-workflow improvements while also filling a critical operational gap left by the prior local IT engineer's departure. Mentored two local hires — the production-line transferee and a newly hired engineer — to autonomous development capability before returning to Taiwan, restoring local development continuity.
